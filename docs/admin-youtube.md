# Наш YouTube в админке

Раздел `/cinema/youtube` работает только в служебном контуре. Backend предоставляет
JWT-защищённые маршруты `admin/cinema/youtube`. Публичное приложение не импортирует
провайдеры мониторинга и не регистрирует эти маршруты.

Используется закреплённый `youtubei.js@18.3.0` — неофициальный клиент внутреннего
интерфейса YouTube (InnerTube), **не YouTube Data API**. Не требуются Google Cloud,
API-ключ, OAuth, cookies, пароль или установка Python. Читаются только публичные
данные; ограничения YouTube не обходятся. Клиент загружается лениво при синхронизации.
JS-плеер YouTube не скачивается/не исполняется (`retrieve_player=false`).

## Настройка

1. При первом деплое применить обычную миграцию
   `1793200000000-create-admin-youtube-monitor.ts` к **служебной** БД
   (`yarn apply-migration` с обычным внутренним окружением). Существующий внутренний
   DEV/PROD автодеплой уже выполняет миграции. Публичному серверу БД/миграции не нужны.
2. Открыть «Управление кинотеатром → Наш YouTube».
3. Вписать до 20 каналов, по одному на строку: `@handle`, channel ID `UC…` или
   `https://www.youtube.com/@handle`. Поддерживаются также `/channel/UC…`, `/c/name`,
   `/user/name` и ссылки на вкладки `/videos`, `/shorts` этих каналов.
4. Сохранить список и нажать «Обновить с YouTube». Сохранение само по себе не запускает
   сетевую работу; далее настроенные каналы обновляются по расписанию раз в 30 минут.

По умолчанию новые ENV не нужны. Список и кеш хранятся в отдельных таблицах
`admin_youtube_sources` и `admin_youtube_videos`, переживают рестарты. Удаление канала
из списка отключает его обновления и скрывает видео; собранные данные не удаляются.
Повторное добавление того же источника возвращает его кеш. Совпадающие ссылки
нормализуются, алиасы одного channel ID используют общий кеш видео.

### Выделенный прокси (необязательно)

Если служебный сервер не имеет доступа к YouTube, задайте `YOUTUBE_PROXY_URL`
в **служебном** runtime ENV: HTTP(S) CONNECT URL, при необходимости с логином
и паролем. Спецсимволы в реквизитах должны быть URL-encoded. Это секрет сервера:
не помещайте его в Git, публичный ENV, браузер или общие `HTTP_PROXY`/`HTTPS_PROXY`.
После изменения требуется пересоздать контейнер backend с обновлённым ENV.

`undici@6.29.1` создаёт отдельный dispatcher только для запросов YouTube reader.
Остальной backend не использует этот прокси. Список допустимых YouTube-хостов,
запрет редиректов, проверка TLS и лимиты сохраняются. При недоступном/неверном
прокси прямого резервного соединения нет. Публичный runtime запрещает эту ENV,
а адреса публичного контура не принимаются в качестве прокси.

Для безопасного изменения существующего ENV предусмотрен
`deploy/internal/set-youtube-proxy.py /path/to/runtime.env`: URL передаётся
через stdin, не аргументом командной строки. Скрипт сохраняет резервную копию,
меняет только `YOUTUBE_PROXY_URL`, атомарно записывает ENV с правами `0600`
и не печатает реквизиты. Сам скрипт не перезапускает сервисы.

## Данные и ограничения

### Импорт только Shorts

В админке добавлен отдельный редактор «Обработать Shorts». Это не часть фонового
обновления метаданных: скачать можно только явно выбранный, подтверждённый киноклип
из вкладки Shorts, с проверенным владельцем и включённым каналом. Старый неизвестный
формат (`isShort=null`) и обычное видео отклоняются сервером до обращения к worker.
Нужна миграция `1793300000000-add-youtube-short-format.ts` и обновление каналов.

Worker short-content включается отдельно через `YOUTUBE_IMPORT_ENABLED=true` и
собственный секретный `YOUTUBE_PROXY_URL`; внутренний access token обязателен.
Он предлагает OCR-маски имён/знаков и защиту текста, поддерживает ручные области,
временные интервалы и поиск знака по образцу во всём ролике. Рекламу можно закрыть
сплошной маской. Пересечение с защищёнными субтитрами блокирует экспорт; OCR может
пропускать знаки и текст, поэтому проверка оператором обязательна. Автопубликаций нет.
Оригинал не заменяется; лимиты и развёртывание описаны в short-content/docs/youtube-imports.md.

- Заголовок, описание, превью, YouTube video ID, дата публикации, доступные публичные
  счётчики лайков и комментариев. Просмотры, тексты комментариев, аналитика удержания,
  личные данные и видеофайлы **при синхронизации метаданных** не сохраняются.
- Просмотр — стандартный iframe `youtube-nocookie.com`, создаётся только по нажатию
  «Смотреть видео». Закрытие окна сразу размонтирует плеер. Если встраивание ролика
  запрещено его владельцем, есть ссылка для открытия на YouTube.
- Счётчики сохраняются с той точностью, которую отдал YouTube (`1.2K` остаётся `1.2K`).
  Неизвестное/скрытое значение — `null`, а не `0`. Если запрос комментариев упал,
  предыдущий счётчик и его дата остаются, рядом показывается предупреждение.
- За проход опрашивается до **50 видео и Shorts суммарно на канал**, форматы
  чередуются, до трёх страниц списка на формат. Это не импорт полной истории канала.
  Найденные ранее видео сохраняются; у старых вне текущей выборки останется своя
  прежняя дата обновления. Есть фильтр по каналу и серверная пагинация по 12 видео.
- Обработка последовательная, пауза 500 мс между роликами. `getInfo` внутри библиотеки
  делает пару запросов метаданных; видео не декодируется и ИИ не используется.
  HTTP timeout — 20 с, бюджет канала — 3 мин, прохода — 20 мин (текущий HTTP-запрос
  может закончиться чуть позже бюджета). Соседние проходы защищены PostgreSQL advisory
  lock, повторный запуск в том же процессе объединяется с активным.
- При HTTP 403/429 клиент приостанавливает новые запросы на 30 минут. Резервных прокси,
  ротации адресов, обхода CAPTCHA/авторизации и автоматических повторов нет. Публичные
  счётчики и доступность не гарантируются: YouTube может изменить внутренний формат,
  запретить встраивание или ограничить серверный IP. При ошибках кеш не обнуляется.
- Ввод ограничен ссылками на каналы YouTube. Внешний клиент принимает только HTTPS
  к разрешённым YouTube-хостам и запрещает редиректы; запросы на другой контур,
  произвольные URL и скачивание медиапотоков не предусмотрены.

## HTTP

- `GET /api/admin/cinema/youtube?page=1&pageSize=12&source=@handle` — читает кеш,
  список каналов, состояние последнего обновления и локальный статус синхронизации.
- `PUT /api/admin/cinema/youtube/accounts`, `{ "accounts": ["@handle"] }` — атомарно
  сохраняет полный список. Пустой массив отключает все источники без удаления кеша.
- `POST /api/admin/cinema/youtube/sync`, `{}` — `202`, фоновый проход, без ожидания
  завершения в HTTP-запросе. По умолчанию пустой список не делает внешних запросов.
